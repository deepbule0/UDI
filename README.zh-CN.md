# 用户定义界面（User-Defined Interface，UDI）

**由你定义的软件。**

桌面：[简体中文](https://deepbule0.github.io/UDI/?lang=zh-CN) · [English](https://deepbule0.github.io/UDI/?lang=en) · 手机：[简体中文](https://deepbule0.github.io/UDI/mobile.html?lang=zh-CN) · [English](https://deepbule0.github.io/UDI/mobile.html?lang=en) · [通用框架](docs/zh-CN/FRAMEWORK.md) · [阅读中文提案](docs/zh-CN/POSITION-PAPER.md)

UDI 提出一种应用模型：平台提供**有用的内容、可信功能和良好的默认体验**，普通人可以通过**智能体对话或熟悉的控件**，调整信息如何组织、哪些功能更容易找到，以及受支持的任务如何衔接，再把这套使用体验分享给别人。

**UDI 是一个通用应用框架。** 音乐、阅读、照片、出行、研究等应用都可以采用同一套生命周期。每个宿主通过专门的领域契约，提供自身支持的内容、组件与操作。[框架草案](docs/zh-CN/FRAMEWORK.md)定义共同职责、十项拟议要求，以及兼容性声明和验证证据的边界。当前研究演示只是该框架的一个有限领域配置（profile），不代表全部范围。这些文档是公开讨论提案，尚非获认可的行业标准。

## 应用场景示例

| 应用领域 | 可复用体验示例 | 每个人分别提供 |
| --- | --- | --- |
| 音乐 | 以专辑为主、持续显示队列并提供受支持歌单控件的播放器 | 自己的音乐账户、音乐库与访问选择 |
| 阅读 | 按主题组织内容，并在正文旁显示笔记的阅读视图 | 自己的文档、批注与权限 |
| 研究 | 优先显示失败实验，并支持审阅后创建汇总笔记的工作空间 | 自己的研究记录与能力授权 |

用户可以预览兼容的共享体验，选择**使用**，再通过智能体或设置式面板继续调整。服务集成由宿主处理。

**可复用的是一套应用使用方式：**包括界面、可用信息的组织方式、偏好设置和受支持的交互流程。平台支持范围、账户权限和操作确认仍决定它能做什么。[音乐应用示例](docs/zh-CN/EXAMPLES.md)展开其中一种假设应用。

本仓库通过一个持久化的**研究工作空间**，实现有限的领域配置。当前 Schema 和运行时支持研究记录；音乐、阅读等领域示例仍是应用设想。此原型尚未实现这些服务集成，也不能生成任意应用。

**状态：实验性版本 v0.4.0。** 此版本新增简单分享链接、可视化示例预览、采用后重新选择数据访问，以及表单创建本地工作空间。智能体对话与控制面板、高级数据工具和公开 GitHub 发现功能继续可用。应用版本 **0.4.0**、通用框架草案 **0.1** 与可执行的 Core 研究 Schema **0.1** 分别描述不同范围。本仓库包含可运行的浏览器原型和规范草案，尚不构成生产级安全系统或已确立的标准。

**术语说明：** “user-defined interface”这一表述及其缩写 **UDI** 已出现于 Wixon、Whiteside、Good 和 Jones 在 CHI 1983 发表的论文 [Building a User-Defined Interface](https://michaelgood.info/publications/usability/building-a-user-defined-interface/) 中。本项目沿用这一术语，描述本文提出的、由智能体参与的界面生命周期，不主张对名称的首创权。

## 像普通用户一样试用

1. 打开[桌面演示](https://deepbule0.github.io/UDI/?lang=zh-CN)或[手机演示](https://deepbule0.github.io/UDI/mobile.html?lang=zh-CN)，直接使用默认研究工作空间。
2. 在**智能体**中输入 `只显示失败实验`，审阅后应用更改；也可以使用设置式的**控制面板**。
3. 选择**分享这个界面**，为这套体验起名，然后**复制链接**或使用设备分享菜单，发给朋友。链接分享无需账号、文件上传或 GitHub 操作。
4. 接收者会看到使用虚构示例记录的可视化预览。点击**使用这个界面**后，在**数据**中选择一个示例工作空间，或**创建我的工作空间**，再明确允许读取。每个人保留自己的记录与权限。
5. 打开**社区**，选择**试试这个界面**，先预览其他体验，再决定使用或继续调整。

分享链接本身包含受支持的界面定义，**不会**自动创建公开社区帖子。公开发现目前通过**高级发布**下的 GitHub 提交实现，需要单独操作。链接可能被转发，分享前请检查名称和描述。

## 智能体、数据与社区

打开[**智能体**](https://deepbule0.github.io/UDI/?lang=zh-CN&view=agent)与离线指令助手对话，或选择**控制面板**，通过设置式控件管理界面、数据源和权限。两条路径都先生成待审核的更改。可尝试 `切换到 Atlas lab`、`撤销实验访问权限` 或 `只显示失败实验`。托管助手仅支持有限语法，本地开发可选用模型。

打开[**数据**](https://deepbule0.github.io/UDI/?lang=zh-CN&view=access)，选择让界面使用哪些内容。可以体验公共虚构示例，也可以选择**创建我的工作空间**，填写名称和一条实验结果。新的个人工作空间默认关闭访问权限；**允许读取此工作空间**只授予请求的读取权限，创建笔记仍需单独选择。内容保存在此浏览器中，尚未实现真实账户连接。JSON 导入、备份和技术详情保留在**高级数据工具**中。

打开[**社区**](https://deepbule0.github.io/UDI/?lang=zh-CN&view=community)，浏览通过校验的公开 GitHub 帖子和明确标识的项目示例。可视化预览使用示例数据，不读取个人记录。选择**使用这个界面**或**复制并使用**后，再自行选择数据和授权。如需创建可公开发现的帖子，请展开**高级发布**，审阅内容后使用自己的 GitHub 账号提交。仅打开编辑器不会创建帖子。详见[社区与个人数据指南](docs/zh-CN/COMMUNITY.md)。

<img src="docs/assets/udi-agent.zh-CN.png" width="280" alt="智能体对话与设置式控制面板" /> <img src="docs/assets/udi-community.zh-CN.png" width="280" alt="社区发现、发布与项目示例界面" />

智能体只能修改平台和运行时支持的内容。当前演示支持研究视图、筛选、分组、显示隐藏、数据选择、权限以及经过确认的本地笔记操作。更完整的音乐场景仍需要音乐领域的集成。

## 手机应用演示

用手机打开 [UDI Pocket](https://deepbule0.github.io/UDI/mobile.html?lang=zh-CN)。它采用卡片、底部导航和审核面板，与桌面应用共享界面包、校验、权限及操作确认的生命周期。这是可安装的渐进式网页应用（PWA），未提供 App Store 或 Google Play 安装包。

1. 在**首页**浏览实验卡片。打开**智能体**，选择**只显示失败实验**，检查提案后点击**应用更改**。
2. 在**数据**中选择公共示例，或用简短表单创建本地工作空间，再批准读取。添加本地笔记操作后，仍需单独授予写入权限，预览确切内容并确认。
3. 选择**分享这个界面**发送链接，也可以在**社区**中发现并调整他人的体验。**高级界面工具**保留文件导出与导入，**高级发布**提供公开 GitHub 发帖流程。

通过手机浏览器的安装菜单添加到主屏幕。顶部 **?** 按钮可打开**关于与安装**。首次成功联网加载后，请等待**可离线使用**提示，再依赖内置演示的离线功能。Android/iPhone 安装、离线行为和存储限制见[手机使用指南](docs/zh-CN/MOBILE.md)。不同设备不会自动同步；iPhone 主屏幕网页应用与 Safari 的存储也相互独立。

## 本地运行

需要 Node.js **22.12+** 和 npm。

```sh
git clone https://github.com/deepbule0/UDI.git
cd UDI
npm ci
npm run dev
```

打开 Vite 输出的本地网址即可进入桌面应用；在网址后添加 `/mobile.html?lang=zh-CN` 可进入手机应用。无需 API 密钥或账号。默认规划器是一个**能力有限的确定性意图解析器**，界面中会明确标示。应用内置两组虚构数据，没有连接真实账号。字体随应用一起提供。

演示中可通过 **EN / 中文** 切换语言。语言切换只影响显示，不修改界面包定义、数据绑定或已授予的能力。离线解析器同时接受英语和支持范围内的中文指令。

可选的 [Ollama 桥接服务](docs/zh-CN/AGENT.md)允许本地安装的模型提出操作，并沿用同一套校验与审核流程。在记录的本地环境中，两个真实模型冒烟测试用例和一个浏览器集成用例已通过。这些经过选择的开发示例不能证明模型的整体质量；相关[失败与观察记录](docs/zh-CN/MODEL-OBSERVATIONS.md)也已公开。

## 一分钟理解这个想法

设想一位研究者提出：

> 显示失败的实验、实验记录中的提交、我的研究文献库和即将到来的截止日期。随着项目推进，让我可以持续调整这个工作区。

生成的工作空间应当在对话结束后继续可用。另一位研究者应当能预览并采用这套体验，同时使用自己的数据，独立决定授权。音乐场景也是同一个原则：复用适合某个人的应用使用方式，每个人仍保留自己的内容与账户。

这背后使用的是**界面包（interface package）**：经过校验的定义，描述视图、逻辑数据源、能力请求和受支持的操作。每次安装分别提供自己的数据绑定、授权和执行历史。JSON 是当前实现采用的格式，使用和分享体验无需编辑它。

UDI 将这一生命周期作为核心设计问题：

```mermaid
flowchart LR
  I[用户意图] --> P[规划器提案]
  P --> V[校验与审核]
  V --> S[版本化界面包]
  S --> R[确定性运行时]
  D[实例数据绑定] --> R
  G[实例能力授权] --> R
  R --> U[可用工作区]
  U --> I
  S --> F[导出 / 派生 / 安装]
```

## 本项目的贡献

- 一份包含结构校验和语义校验的[界面包契约草案](spec/udi.schema.json)：限定组件类型、声明逻辑数据源、检查版本并声明能力。
- 一个[参考运行时](src/core/runtime.ts)：按实例解析数据源，同时检查**已声明**和**已授予**的能力。
- 可审核的[修订提案](src/core/planner.ts)：精确检查基础状态，以原子方式应用变更，并支持在界面中撤销。
- 经过确认的本地笔记创建：预览与实例、修订版本、定义和确切载荷绑定；执行时再次检查授权与源数据。
- 仅包含定义的导出与导入、本地派生副本、两组相互独立的数据集绑定，以及可复现的校验和浏览器测试。
- 智能体对话与设置式控件、本地工作空间创建表单、可视化示例预览、直接分享链接，以及基于公开 GitHub 帖子的社区和审核后的发布、使用流程。JSON 数据工具保留供高级使用。
- 中英双语手机 PWA：卡片视图、底部导航、离线应用缓存，以及同一套修订审核和操作检查。
- 一篇[立场论文](docs/zh-CN/POSITION-PAPER.md)、[相关工作分析](docs/zh-CN/RELATED-WORK.md)、[威胁模型](docs/zh-CN/SECURITY.md)和[评估计划](docs/zh-CN/EVALUATION.md)。
- 一份通用[框架草案](docs/zh-CN/FRAMEWORK.md)：区分可复用体验、平台契约与个人实例，提出共同要求，并限定跨应用领域的兼容性声明。

这是一项关于系统整合与生命周期的提案。生成式界面、声明式渲染、终端用户编程和能力管控都已有大量先行工作。UDI 不主张发明了这些技术。

## 两分钟演示

1. 选择 **Show only failed experiments（仅显示失败的实验）**。检查提案；在点击 **Apply change（应用变更）**前，表格保持不变。
2. 在实例选择器中选择 **Atlas lab**。同一个界面包会显示另一个项目的记录。**Undo（撤销）**会恢复之前的界面定义，同时保留当前的数据绑定。
3. 添加 **related papers（相关论文）**。第五种组件类型会从已声明的本地文献库数据源中出现。
4. 打开一次实验运行，查看其记录的提交。这是通过显式 ID 提供的来源追溯，不是因果分析。
5. 添加 **review-note action（审阅笔记操作）**。在 **Data & access（数据与访问权限）**中授予 `notes.write`，然后在工作区预览并确认本地写入。
6. 选择**分享这个界面**，然后**复制链接**。在另一个浏览器环境中打开，预览后选择**使用这个界面**，再选择工作空间并批准读取。桌面的**高级工具**或手机的**高级界面工具**也保留文件导出与导入。使用共享界面会清除授权；记录内容和笔记不会随界面转移。

## 与现有工作的关系

| 工作 | 其文档说明的重点 | 与 UDI 的关系 |
| --- | --- | --- |
| [A2UI](https://github.com/a2ui-project/a2ui) | 通过客户端组件目录渲染可更新的声明式智能体界面 | 可作为候选渲染层；UDI 当前的格式并不兼容 A2UI |
| [AG-UI](https://docs.ag-ui.com/introduction) | 智能体后端与前端之间的事件、状态、工具和交互 | 可用于未来提案与审核事件的传输 |
| [MCP Apps](https://github.com/modelcontextprotocol/ext-apps) | 由工具提供、嵌入宿主的界面资源 | 可作为候选宿主或集成入口 |
| [json-render](https://github.com/vercel-labs/json-render) | 基于组件目录约束的界面生成与渲染器 | 可替代本原型的小型渲染器 |

以上比较描述各项目的侧重点，不意味着这些项目无法支持持久化、权限或界面包复用。v0.4 没有提供互操作适配器。详见[来源与边界](docs/zh-CN/RELATED-WORK.md)。
