# Related work and positioning

Sources checked October 17, 2026. Descriptions below summarize each project's documented scope. They are not an exhaustive feature audit or a claim that a project cannot implement UDI-like workflows.

## End-user authoring and adaptive interfaces

The exact phrase **user-defined interface** and acronym **UDI** occur in Wixon, Whiteside, Good, and Jones's *Building a User-Defined Interface* (CHI 1983). That work iteratively revised an email command interface around commands generated by novice users, with a hidden operator interpreting unsupported input. The present project does not introduce the term. Its intended contribution is an agent-mediated definition lifecycle with portable packages and instance-local authority. The original paper is available on a coauthor's site: [Wixon et al., 1983](https://michaelgood.info/publications/usability/building-a-user-defined-interface/).

Personal tools and user-controlled environments precede language models. Engelbart's human-augmentation framework considers the combined system of people, artifacts, methods, and language. UDI shares the goal of improving how people organize work; it offers one contemporary implementation proposal, not a historical starting point. [Original report, 1962](https://www.dougengelbart.org/pubs/augment-3906.html).

SUPPLE automatically generates interfaces using optimization. Its contribution makes it especially inappropriate to claim that AI-adaptive interfaces originate with UDI. UDI instead investigates package ownership, continued revision, rebinding, and mediated execution as one lifecycle. [Gajos and Weld, IUI 2004](https://www.eecs.harvard.edu/~kgajos/papers/2004/gajos04supple.shtml).

## What makes a UDI experiment meaningful

Generating a dashboard is insufficient evidence for this proposal. A meaningful experiment should exercise the full loop:

1. Author or select a definition.
2. Bind it to one instance and choose grants.
3. Revise it while preserving operational state.
4. Export the definition without structured instance state.
5. Install it into another instance with new bindings and fresh grants.
6. Measure whether the second user can perform the intended task.

Many existing systems may already support substantial parts of this loop. The claim here is that naming and specifying the loop provides a useful engineering and evaluation target. Whether that integration is a novel research contribution remains to be established through a systematic review and comparative evaluation.

## AI app builders, dashboards, and workflow tools

The useful distinction is architectural, not a rigid product category. A code-generating app builder can produce a persistent application. A dashboard can have rich permissions and data connectors. A workflow system can share definitions independently of credentials. UDI proposes to combine ongoing intent-driven revision with an explicit package–instance contract; it should be assessed against systems implementing that same combination, not a simplified caricature of other tools.
