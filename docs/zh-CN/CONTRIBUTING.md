# 参与 UDI

[English](../../CONTRIBUTING.md) | **简体中文**

最有价值的贡献可以检验这个想法、厘清边界，或提高参考生命周期的可靠性。围绕具体任务的小幅变更，比宽泛的新抽象更容易评估。

## 开发

```sh
npm ci
npm run dev
npm run check
npx playwright install chromium
npm run test:e2e
npm run test:pwa
npm run evaluate
```

核心逻辑位于 `src/core/`，渲染器位于 `src/Workspace.tsx`，应用状态与审查界面位于 `src/App.tsx`，包契约位于 `spec/`，虚构演示数据位于 `src/data/`。可选本地模型桥接服务见 [AGENT.md](AGENT.md)。

手机应用位于 `src/mobile/`，共享持久化状态位于 `src/core/session.ts`。`src/pwa.ts` 处理安装和更新界面，`scripts/pwa.ts` 生成生产环境的 Service Worker。开发时打开 `/mobile.html`。生产构建后再运行 PWA 检查；开发服务器禁用缓存。请保持中英文以及桌面和手机生命周期一致。

## 值得提出的变更

- 经过测试、并明确标注上游版本的 A2UI 或 json-render 适配器。
- 一个可信的只读连接器，具有资源范围授权和结果验证。
- 包含原始输出、失败和可复现条件的真实模型评估。
- 无障碍改进，尤其是文本对比度、键盘导航和小屏幕体验。
- 关于包迁移或可审查修订的可用性证据。

新增组件或操作前，请说明它服务的用户任务、标准化的数据契约、权限要求和失败行为。不要为包加入任意代码执行能力。不要将包的能力请求描述为授权，也不要将通过 Schema 检查描述为隐私保证。

## 拉取请求

说明问题与变更后的行为，提供简短的复现步骤，描述相关验证，并公开局限。更改契约时，同步更新 Schema、规范、演示数据和测试。如果行为不兼容，应讨论版本变更，而不是默默接受未知扩展。

使用虚构或匿名化数据。绝不包含账户令牌、浏览器状态、真实实验日志或私有服务 URL。没有证据时，不要添加贡献者姓名、机构关联、基准结果或背书。

贡献应遵循仓库的 [MIT 许可证](../../LICENSE)。尊重既有工作，准确说明分歧，并让讨论聚焦于行为与证据。
