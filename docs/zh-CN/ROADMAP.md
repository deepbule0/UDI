# 以证据为依据的路线图

[English](../ROADMAP.md) | **简体中文**

本路线图记录已交付范围与后续推进条件，不是交付承诺。UDI 的[通用框架](FRAMEWORK.md)讨论具备能力的平台中的用户定义体验；可执行的 **Core 0.1 研究配置**只是一个有界实现，不是通用应用模式。

## v0.1：让生命周期可检查

已交付：严格的包模式、语义检查、五种视图、经审阅的有界修订、撤销、独立示例绑定、本地能力控制、经确认的本地笔记、界面包导出/导入/派生、离线解析器、可选的本地模型桥接服务，以及可复现检查。

推进条件：其他开发者可以独立运行演示、理解局限，并在无需帮助的情况下复现迁移闭环。

## v0.2：将同一生命周期带到手机

已交付：中英双语 UDI Pocket，包含触摸卡片、安装清单、离线应用资源缓存和手机验收检查。它与 Studio 使用同一份 Core 0.1 定义和运行时，详见[手机使用指南](MOBILE.md)。原生应用商店安装包、跨设备同步和真实手机连接器仍属后续工作。

## v0.3：提供创作、数据所有权与分享操作

已交付：智能体对话与设置式控件、经审阅的状态变化、个人研究 JSON 导入/下载/删除，以及轻量 GitHub Issues 社区，支持帖子校验、预览、安装、派生，并通过用户自己的 GitHub 账户完成审阅后的发布。项目示例单独标注。这不能证明社区采用、内容治理或通用模型能力。

## v0.4：让普通用户能够复用与分享

已交付：根据所选定义与虚构公开示例数据渲染的可视预览；明确的**使用这个界面**与复制操作；工作区选择与访问授权；基于表单的个人研究工作区创建；以及自包含分享链接，接收方可以先预览、再明确采用。

主要路径是：**试用 → 使用 → 选择工作区并授权 → 个性化 → 分享链接**。用户完成这条路径无需编程、API 或 JSON 文件。智能体对话与常规控件保持互补；界面包文件和 GitHub 公开发布是高级选项，详见[社区指南](COMMUNITY.md)。

发布材料将通用框架与研究参考配置区分开。示例领域包括学习、阅读、旅行、照片、效率和音乐；这些服务集成均未实现。应用 v0.4.0 仍使用 Core 0.1，托管版对话仍是有界确定性解析器，没有托管大语言模型。

推进条件：未参与开发的普通用户能够完成这一生命周期，理解分享与授权了什么，并能在无需技术帮助的情况下从不想要的变化中恢复。

## 下一步：与普通用户测试完整体验

招募不同技术经验的人，包括不创作软件的用户。将链接复用与技术性界面包交换、等效固定应用的配置过程作比较。

测量获得有用体验所需时间、完成错误、求助、无障碍、对共享与私人信息的理解、访问决策和成功恢复。既测试项目示例，也测试其他参与者创作的体验。对未见过的语言请求另行评估，区分正确理解与通过模式校验，公开不受支持的请求与失败。

推进条件：有证据表明，UDI 能改善调整或复用，同时不会造成不可接受的可预测性、隐私或控制权损失。当前符合性测试不能证明这些结果。

## 随后：实现一个真实提供方适配器

选择具备有用内容、清晰默认体验，以及至少一种超出外观修改的受支持操作的提供方。可以来自音乐、阅读、学习、旅行、照片或效率领域；领域选择应遵循实际用户需求，而不是将 UDI 重新限定在该领域。

将凭证与策略放入可信网关。定义注明版本的数据源和操作契约、资源范围、撤权和明确的失败行为。从限定范围的读取开始；只有精确效果审阅、事务语义及有有效期的一次性授权就绪后，才引入有界写入。提供方权利与受支持 API 仍然构成约束。

推进条件：经过独立审阅的集成证明，用户可以个性化受支持的呈现、数据组织和有用交互，同时由提供方继续执行访问与效果约束。

## 随后：证明兼容性，而非假设兼容性

实现一个面向已有声明式渲染器或第二个独立运行时的版本化适配器。公开能力协商、不受支持特性的处理、迁移和符合性样例。区分呈现适配与执行兼容。

推进条件：成功完成跨实现复用实验，记录损失与失败。在同一个运行时内重新绑定数据或打开分享链接，不足以证明跨提供方或生态层面的可移植性。

## 更长远：更广的工作流与具备治理机制的分发

考虑事件与工作流契约、后台执行、并发、恢复、包完整性、来源、内容治理、举报和更大规模的发现。语义图谱与后台智能体是可能的扩展，并非 UDI 的前提。轻量 GitHub 公开帖子已经可用，但不代表成熟的分享服务或社区采用证据。

推进条件：反复出现的用户需求证明增加复杂度的必要性，安全模型能够解释每一种新效果。框架草稿需要独立实现、公开审阅和互操作证据，才能成为可信的标准化候选，而不只靠命名。
