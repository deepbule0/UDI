# 评估：已有证据与待解问题

[English](../EVALUATION.md) | **简体中文**

## 当前检查能够证明什么

`npm run check` 执行 TypeScript 验证、核心与适配器单元测试，以及生产构建。`npm run test:e2e` 覆盖桌面和手机浏览器中的生命周期。构建后，`npm run test:pwa` 检查生产环境的安装清单、图标、离线重载和缓存隔离。`npm run evaluate` 根据公开的[用例集](../../eval/cases.json)生成 [evaluation-results.json](../evaluation-results.json)。

符合性用例集包含 11 个受支持的意图和 5 个不受支持的请求，其中一个同时包含受支持和不受支持的内容。另外三个不变量检查定义的导出再导入、不同数据集的解析，以及导出时排除演示记录和本地绑定 ID。这些回归用例是针对明确语法编写的，既不是保留测试集上的语言理解测试，也不是与其他项目的比较。

核心测试覆盖：无效字段和版本、拒绝可执行组件、重复 ID、数据源与能力替换、不兼容的实体绑定、导入限制、导出边界行为、自由文本泄漏、过期修订、原子性失败、请求与授权分离、动作确认、撤销授权、外部实例、源数据变化，以及格式错误的模型输出。

浏览器验收覆盖：应用前审查、持久化、撤销、数据集重新绑定、撤销授权后拒绝渲染、经过显式授权和确认的笔记创建、导出再导入并清除授权、窄屏溢出，以及基于固定测试数据的模型响应。

2026 年 10 月 17 日的本地验证通过了 150 项核心、适配器、本地化、控制器、数据、社区、会话与分享测试、Edge 中的 46 个浏览器场景、3 项生产 PWA 检查、16 个确定性意图用例、3 个生命周期不变量、TypeScript 检查和生产构建。GitHub 托管的验证尚未成功运行，详见 [Actions](https://github.com/deepbule0/UDI/actions/workflows/ci.yml)。

手机检查在 390 × 844 和 430 × 932 像素下模拟触摸操作，覆盖标签导航、审核与应用、撤销、独立授权、语言链接、溯源面板焦点、界面包迁移和确认后创建笔记。生产检查验证 PNG 安装图标、保留状态的中文离线重开、离线时未缓存 API 请求失败，以及不删除同源的其他应用缓存。这些是 Chromium/Edge 检查，不是实体 Android/iPhone 的安装测试，也不构成 Safari 兼容性认证。

本地化检查覆盖中英文直达链接、语言偏好持久化、中文意图的应用前审阅、不受支持的复合请求、窄屏控件，以及语言切换前后界面包和实例状态保持一致。导出保留规范中的机器定义，不会将翻译后的显示标签写入界面包。

真实本地模型的两个指定直接调用和一个浏览器集成场景也已通过。输出、模型摘要、运行时与宿主元数据记录在 [model-smoke-results.json](../model-smoke-results.json) 和 [bridge-smoke-results.json](../bridge-smoke-results.json) 中。早期出现的空输出和无效面板引用在 [MODEL-OBSERVATIONS.md](MODEL-OBSERVATIONS.md) 中公开说明。尝试过程中调整了提示词。这些是开发阶段的冒烟测试观察，不是保留测试集上的质量结果。

这些检查表明参考生命周期在所选条件下能够工作。它们不是安全证明、无障碍认证、可用性研究、跨运行时可移植性演示，也不是性能排名。“通过导出检查”表示排除了结构化字段和选定的哨兵值，并不表示能够检测任意私人文本。

智能体检查覆盖对话与设置的审核一致性、并发状态变化后拒绝旧提案、添加笔记请求不触发写入，以及可选模型载荷最小化。个人数据检查覆盖严格 JSON 校验、独立命名空间、授权前拒绝渲染、重载、下载和确认后删除。社区测试通过模拟 GitHub 响应与编辑器，验证解析、帖子发现、安装清除授权和隐私边界，不发布真实 Issue，不证明社区采用情况，也不声称验证了 GitHub 登录及最终提交的端到端流程。

分享链接检查还覆盖 Unicode、原始与压缩封装、规范编码、解压上限、不支持的版本及实例状态排除。浏览器检查覆盖 React StrictMode 下首次打开链接、预览不修改状态、主动采用、清除全部授权但保留个人记录／笔记／聊天、取消、无效链接、中文手机分享，以及通过表单创建工作空间并单独允许读取。剪贴板与公开编辑器操作使用模拟，不发送真实消息或帖子。通用目标及其与有限配置的区别见[框架要求](FRAMEWORK.md)。

## 建议的比较评估

保持连接器测试数据、任务结果和权限条件一致，对比：

1. 通过直接配置控件操作的固定仪表盘。
2. 每次请求后整体重新生成的智能体工作区。
3. 采用经过审查的增量操作、并拥有独立实例授权的 UDI 式包。

使用 A2UI、AG-UI 或 json-render 的实现，不会自动构成一个竞争实验条件：这些工具同样可以实现 UDI 生命周期。应比较具体行为，而非协议名称。

测量指标：

| 问题 | 测量方式 |
| --- | --- |
| 修订是否有帮助？ | 正确完成任务、编辑耗时、纠正次数、意外丢失有用视图的次数 |
| 迁移是否有帮助？ | 在第二个数据集中成功安装、映射纠正次数、获得第一个有用视图的时间 |
| 用户是否理解权限？ | 对允许动作的正确预测；发现新增访问请求的能力；不恰当授权的次数 |
| 生成的输出是否可靠？ | Schema 接受率、任务语义正确性、对不受支持请求的拒绝、修复频率 |
| 系统是否实用？ | 规划器延迟与成本、渲染延迟、连接器调用次数、感知到的打断程度 |
| 导出是否保护了实例状态？ | 结构化泄漏测试、植入文本的泄漏、人为审查错误 |

先开展形成性的可用性试点，并在声称量化改进之前公开研究方案。后续比较研究应说明招募方式、任务难度、顺序平衡、排除标准、样本量依据和不确定性的报告方法。不能仅凭运行时符合性推断用户收益。

## 可复现性要求

模型实验应公开模型标识与摘要、硬件和运行时、完整提示词与 Schema、数据集版本、随机性设置、重试、失败输出、人工修正，以及总推理成本。区分“语法上被接受”和“符合用户意图”。加入未见过的措辞、歧义请求、权限提升、恶意源内容和无效绑定。评估模型拒绝和不受支持的请求，不要默默将它们映射为近似操作。
