# 介绍 UDI：用自己的方式使用应用

[English](../ANNOUNCEMENT.md) | **简体中文**

平台可以提供内容与功能，而不必要求所有人使用同一种体验。

**用户定义界面（User-Defined Interface，UDI）**是一种框架：平台提供有用的内容、受支持的操作和可用的默认应用，用户通过智能体或熟悉的控件，塑造自己的使用方式。用户可以改变呈现、交互、数据组织和受支持的工作流，再像分享链接一样分享这套体验。

示例领域包括学习、阅读、旅行、照片、效率和音乐。阅读服务可以提供按主题组织的视图，旅行工具可以提供每日行程，音乐服务可以提供专辑与队列的组合视图。每个提供方定义自己支持的内容与操作。这些例子说明可能的应用，本仓库尚未实现相应集成。

值得分享的对象是**可复用的使用体验**：在提供方支持的范围内，应用如何呈现、如何工作。接收方使用自己的数据和权限。普通用户不应为了参与而必须编程、调用 API、上传 JSON 界面或理解包格式。

实验性 **v0.4.0** 应用在参考演示中提供这条普通用户路径：

1. **试用**：通过虚构示例数据，直观看到界面的使用效果。
2. **使用**：明确选择采用这个界面。
3. **选择工作区并授权**：决定它可以使用哪些数据；个人研究工作区可以通过表单创建。
4. **个性化**：使用智能体对话或设置式控件继续调整。
5. **分享链接**：让他人预览并使用自己的副本。

可以试用[桌面版 UDI Studio](https://deepbule0.github.io/UDI/?lang=zh-CN) 或[手机版 UDI Pocket](https://deepbule0.github.io/UDI/mobile.html?lang=zh-CN)，均支持简体中文与英文。Pocket 可以安装为网页应用，在应用资源缓存后离线使用；它不是原生应用商店安装包，也不提供设备同步。详见[手机使用指南](MOBILE.md)。

发现界面时，UDI 项目示例与真实公开社区帖子分别标识。分享链接无需账户或文件上传。在本原型中，公开列表仍通过**高级发布**下经过审阅的 GitHub 交接完成；技术性界面包导入/导出保留在高级工具中。详见[社区指南](COMMUNITY.md)。

在交互背后，可复用定义与私人实例分离；私人实例保存数据绑定、授权、记录、笔记和活动。智能体提出有界变化，宿主校验结果并管控数据访问及实际操作。共享名称与介绍仍需要审阅，因为其中可能含有个人文本。

**通用框架**大于当前演示。应用仅实现 **Core 0.1 研究配置**：实验视图、筛选与分组、研究文献库、截止日期、本地工作区和经确认的本地审阅笔记。它没有实现音乐播放、真实提供方连接器或通用工作流引擎。托管版对话使用小型确定性命令语法，没有托管大语言模型；可选的本地 Ollama 桥接服务可以提出同一组受支持操作。

UDI 是带有可运行参考实现的设计框架草稿，不是已批准的标准，也未证明跨应用兼容。[框架文档](FRAMEWORK.md)、[立场论文](POSITION-PAPER.md)和[研究配置规范](SPECIFICATION.md)明确区分了这些层次与边界。

它建立在终端用户编程、自适应界面和生成式界面的既有工作之上。A2UI、AG-UI、MCP Apps 和 json-render 是相关基础，本原型不声称取代这些项目。名称也有历史：Wixon 及其同事已在 CHI 1983 中使用 “user-defined interface” 和 “UDI”。本项目不主张首创这些术语，详见[相关工作](RELATED-WORK.md)。

接下来的问题需要证据：普通人能否可靠地修改与复用体验、理解其访问范围，并以更少求助完成有用的任务？真实提供方适配器、注明版本的渲染器适配器、可复现的模型评估和终端用户研究，将帮助回答这些问题。[路线图](ROADMAP.md)给出了推进条件。
