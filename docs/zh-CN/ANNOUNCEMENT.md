# 介绍 UDI：由你定义的软件

[English](../ANNOUNCEMENT.md) | **简体中文**

AI 生成界面之后，应该发生什么？

结果应该成为你可以保留、理解、修改，并结合自己的数据复用的东西。这一问题是 **User-Defined Interface（用户定义界面，UDI）** 的起点。

UDI 将可复用的界面包与个人实例分开。包描述视图、逻辑数据源、能力请求和受支持的动作。实例提供自己的绑定、授权、记录和历史。智能体提出修订，确定性的运行时进行验证，用户审查有意义的变更，并批准产生实际效果的操作。

当前实验性版本 v0.3.0 包含一篇立场论文、一份可执行的规范草案，以及两个演示：[桌面版 UDI Studio](https://deepbule0.github.io/UDI/?lang=zh-CN) 和[手机版 UDI Pocket](https://deepbule0.github.io/UDI/mobile.html?lang=zh-CN)。你可以修订视图、切换数据集、检查提交来源、添加文献库面板、审查权限、经确认后创建本地笔记，以及导出或重新安装定义。两个演示均支持简体中文和英文。

智能体标签现提供对话与设置式控件，用于审核后的界面、数据源和权限更改。数据管理区分平台示例与浏览器本地的个人 JSON 导入。社区可发现并安装通过校验的公开 GitHub 帖子，并准备你自己的帖子，在 GitHub 最终提交。项目示例与社区活动分别标识，详见[社区指南](COMMUNITY.md)。

UDI Pocket 是可安装的网页应用，提供卡片视图、五个底部标签，以及应用资源缓存后的离线使用。它沿用 Core 0.1 的界面包与运行时，没有原生应用商店安装包或设备同步。详见[手机使用指南](MOBILE.md)。

它的范围刻意保持精简。默认规划器使用有限的离线语法，数据是虚构的，浏览器权限检查用于演示，不是生产授权。项目另提供可选的本地 Ollama 桥接服务，用于试验模型生成的操作。

UDI 建立在终端用户编程、自适应界面和生成式界面的既有工作之上。A2UI、AG-UI、MCP Apps 和 json-render 是相关基础，本原型不声称要取代它们。本提案聚焦于让生成界面周围的生命周期变得明确、可测试。

这个名称也有历史：Wixon 及其同事已在 CHI 1983 使用过 “user-defined interface” 和 “UDI”。本项目将这一术语用于这里描述的架构，不声称首创该词。

我将它作为一个实验性想法和可运行的参考实现分享出来；除了代码贡献，我也欢迎对其假设的批评。最初的问题很实际：人们能否可靠地修订这些工具？他人的定义能否结合你的数据变得有用？

运行演示，检查包，并尝试突破这些边界。最有价值的下一步贡献包括：注明版本的渲染器适配器、一个正确限定权限范围的连接器、可复现的模型评估，以及关于包迁移的用户研究。
