# 用音乐应用理解 UDI

[English](../EXAMPLES.md) | **简体中文**

[通用框架](FRAMEWORK.md) · [桌面演示](https://deepbule0.github.io/UDI/?lang=zh-CN) · [手机演示](https://deepbule0.github.io/UDI/mobile.html?lang=zh-CN) · [社区与个人数据指南](COMMUNITY.md)

**音乐是通用 UDI 框架的一种应用示例。** 同一套持久、可分享的体验生命周期，也可以用于阅读、照片、出行、研究等应用，各领域需要对应的平台契约。本页展开一个假设案例；[框架草案](FRAMEWORK.md)定义更广泛的职责与拟议要求。

兼容的音乐宿主可以提供默认播放器、用于受支持个性化的智能体与直接控件，以及预览和采用共享体验的路径。宿主负责底层的服务集成。

**这里的音乐场景描述 UDI 的一种应用设想。当前可运行原型使用研究记录，其 Schema 和运行时尚不支持音乐播放或音乐服务适配器。下方音乐提示词是示意，不能直接在当前演示中执行。**

## 从一开始就有用的应用

平台提供音乐访问、歌曲信息、封面，以及搜索、播放、队列管理和歌单编辑等可信功能，同时提供良好的默认应用。听众打开后就能查找音乐、点击播放。

之后，用户可以逐步调整体验：继续使用平台的内容和受支持功能，同时决定这些功能怎样满足自己的需求。无需先设计应用才能听歌，别人分享的体验也不会单独提供音乐访问权限。

## 定义适合自己的使用方式

**智能体**页面同时提供对话与熟悉的设置式**控制面板**。听众可以说：

> “首页以专辑为主，隐藏热门推荐，并始终显示大一点的播放器。”

> “按作曲家整理我喜欢的音乐，让最近加入的专辑更容易找到。”

> “帮我用选中的歌曲整理一个歌单，保存前让我先检查。”

> “使用这个共享的极简播放器，但把按钮放大，空间足够时把队列放在歌词旁边。”

这些请求涉及一整套体验：呈现方式、可用信息的组织方式、偏好与受支持的操作。可复用定义可以描述以专辑为主的首页、按作曲家分组、持续显示的队列，以及保存歌单前的审阅流程，其含义超出视觉主题。

这里需要清楚区分两种影响。按作曲家组织现有音乐库，可能只改变此人的查看方式；保存歌单则会改变账户数据，需要平台支持相应操作、获得授权并进行适当确认。用户同意之前，智能体应当用易懂的方式说明这种区别。

音乐集成需要先提供相关信息与操作。智能体不能凭空生成缺失的目录字段、获取无权访问的音乐，或绕过账户权限检查。应用受支持的定义后，日常播放、队列切换等仍通过普通控件完成，每次点击无需再次对话或调用模型。

## 分享一种听歌方式

例如，一位听众创建了“极简古典播放器”：

1. 他选择**分享**，为这套体验起名并写一段简介，然后把链接发到聊天中。
2. 朋友打开链接，先看到使用明确标识的示例内容所呈现的可视化预览。
3. 朋友选择**使用这个界面**，选用自己受支持的服务账户或音乐库，审阅它请求读取或修改哪些内容。
4. 两人采用相同的听歌安排，各自使用自己的音乐、“喜欢”、歌单和历史。
5. 朋友可以继续让智能体调整，也可以修改常规控件，再分享自己的版本。

社区让这些体验更容易被发现，人们可以先浏览、试用别人分享的风格，无需从创作开始。直接分享也应当可用，并且不会自动变成公开社区帖子。两种方式都不应要求用户处理面向开发者的界面包格式。

可复用定义描述体验及其功能请求，不转移作者的凭据、私人音乐库记录、收听历史、授权或音乐权利。接收者选择自己的连接与权限。名称和描述仍可能透露私人信息，因此分享时需要用可读的方式检查这些文字。

## 体验当前的研究工作空间版本

桌面和手机演示提供这套生命周期的一个小型可运行版本：

1. 直接使用默认研究工作空间，或打开**社区 → 试试这个界面**，查看共享定义使用虚构示例记录呈现的可视化预览。预览中的操作处于禁用状态。
2. 选择**使用这个界面**或**复制并使用**。这会替换当前定义并清除已有的数据授权，本地记录与笔记仍会保留。
3. 在**数据**中选择公共虚构工作空间，或**创建我的工作空间**。表单只需填写名称和一条实验结果，无需数据文件。新的个人工作空间没有任何授权。
4. 检查易懂的访问选项。**允许读取此工作空间**只批准请求的读取权限，创建笔记仍需单独选择。这些个人内容保存在此浏览器中，尚未实现真实账户连接。
5. 在**智能体 → 对话**中提出受支持的请求，如 `只显示失败实验`；也可以通过**控制面板**做设置式调整。先审阅，再应用。
6. 选择**分享这个界面**，命名后**复制链接**，或使用设备分享菜单。无需账号或上传。接收者先预览定义，再独立决定使用什么数据。

分享链接包含受支持的定义，**不会**创建公开社区条目。当前发现列表使用经过校验的公开 GitHub 帖子和明确标识的项目示例。**高级发布**提供独立的 GitHub 审阅与提交流程，发帖者需要自己的 GitHub 账号。这是原型的分发方式，尚非成熟的消费者市场。

可选的 JSON 导入和数据备份位于**高级数据工具**中。界面文件工具和技术详情仍供开发者及高级用户使用。它们在底层实现可移植性；试用、调整或分享体验，无需先使用这些工具。

## 音乐版本仍需实现什么

| 音乐场景的目标体验 | 当前可运行的研究原型 |
| --- | --- |
| 音乐与可直接使用的默认播放器 | 虚构研究记录与默认工作空间 |
| 通过智能体和设置式控件调整体验 | 有限的中英文指令、可选本地模型桥接与控制面板 |
| 重新组织“喜欢”和音乐库；受支持的歌单操作 | 研究视图、筛选、分组、显示隐藏，以及单独确认的本地笔记操作 |
| 预览、采用、调整并分享听歌体验 | 可视化示例预览、本地复用、直接分享链接及高级公开 GitHub 发帖 |
| 每个人使用自己的账号和音乐库 | 相互独立的本地工作空间绑定与权限；没有真实账户连接器 |

音乐版本需要专门的领域契约、服务集成、组件和播放运行时。阅读、照片或出行同样需要明确记录的领域配置。当前界面包 Schema 支持研究组件。UDI 更广的提案是可复用、可个性化的体验及其生命周期；本仓库在一个有意限定的领域内演示这套生命周期。采用同一个名称不能证明互操作性；接收方宿主必须支持具体契约及操作，详见[框架的兼容性要求](FRAMEWORK.md#6-领域配置与兼容性)。
