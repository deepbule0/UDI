# 用音乐应用理解 UDI

[English](../EXAMPLES.md) | **简体中文**

[桌面演示](https://deepbule0.github.io/UDI/?lang=zh-CN) · [手机演示](https://deepbule0.github.io/UDI/mobile.html?lang=zh-CN) · [社区与个人数据指南](COMMUNITY.md)

UDI 可以用于日常应用。以音乐服务为例：平台提供音乐、支持的功能以及可直接使用的默认界面；用户可以通过智能体重新组织界面，也可以使用常规设置，或采用其他人分享的界面定义。

**这里的音乐应用是 UDI 的应用设想。已发布原型使用研究数据，尚未实现音乐播放或音乐服务适配器。**

## 从完整可用的应用开始

平台提供音频访问、包含歌曲信息与封面的目录，以及搜索、播放、队列管理和歌单编辑等受支持的能力。同时，平台提供可用的默认界面：用户打开应用后就能浏览、点击播放并管理队列。

默认界面是可以继续修改的起点。UDI 不要求每个人先设计应用才能使用；别人分享的界面定义也不能替代底层音乐服务。

## 用智能体或控制面板调整

**智能体**页面同时提供对话和设置式的**控制面板**。用户可以提出：

> “首页以专辑为主，隐藏热门推荐，并在底部保留一个大的播放器。”

> “按作曲家整理我的音乐库。空间足够时，把播放队列放在歌词旁边。”

> “使用这个共享的极简播放器，但把按钮放大，并保留最近播放的专辑。”

这些是音乐场景的示意指令，并非当前研究演示支持的命令。音乐适配器需要先提供相应的数据、组件和操作。智能体据此提出可支持的定义变更，供用户审阅；控制面板则提供另一种做出这些选择的方式。

应用变更后，界面定义会保留。播放、拖动进度和切换队列等日常操作通过应用控件与平台支持的功能执行，每次点击都不需要重新与智能体对话或调用模型。

## 采用其他人分享的界面

例如，一位用户分享了“极简古典播放器”。另一位用户在社区浏览并预览布局和能力请求，然后安装该定义，或创建自己的分支。他们连接的是自己的服务账户或音乐库，并独立选择授权，之后还可以让智能体继续调整设计，再分享自己的版本。

可复用的定义描述界面呈现、工作流程、逻辑数据源和能力请求，不会转移作者的凭据、私人音乐库记录、收听历史或授权。公开发布前仍需检查标题、描述等自由文本，避免包含私人信息。分享布局也不意味着分享音频访问权限。

安装的定义不能为自己授权。例如，修改歌单既需要平台支持相应操作，也需要明确授权；声明需要这种能力，不等于获准使用。界面也不能凭空增加平台未提供的目录字段，或绕过平台的访问检查。

## 已发布演示实现了哪些部分

桌面和手机研究演示实现了相同的生命周期：默认工作区、**智能体**对话与设置式控件、审阅后应用变更、**数据**绑定与权限、个人 JSON 导入，以及**社区**中的发现、预览、安装、分支和经审阅后通过 GitHub 发布。对话结束后，运行时界面仍能继续使用。

托管版智能体使用有限的中英文指令语法。社区是基于 GitHub 的原型，提供项目示例和经过校验的公开帖子，尚非成熟的市场。当前界面包 Schema 支持研究组件，不支持音乐。真正的音乐版本仍需音乐专用契约、适配器、渲染器和播放集成。已实现的发布、安装和数据边界详见[社区指南](COMMUNITY.md)。
